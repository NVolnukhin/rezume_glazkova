# Лендинг-резюме — Глазкова Мария Алексеевна

Одностраничный сайт-резюме инженера-проектировщика BIM с портфолио чертежей.
Без сборки и без бэкенда: статические файлы, которые GitHub Pages отдаёт как есть.

## Что внутри

```
index.html                     вся вёрстка и текст разделов
assets/
  css/style.css                дизайн-система и адаптив
  js/data.js                   данные: дата рождения, периоды стажа, портфолио
  js/app.js                    динамические значения, навигация, карточки
  js/viewer.js                 просмотрщик чертежей
  fonts/                       IBM Plex Sans и IBM Plex Mono (latin + cyrillic)
  img/                         фото, обложка для соцсетей, favicon
  portfolio/                   13 PDF-комплектов и обложки проектов
  vendor/pdfjs/                PDF.js 4.10.38 (legacy-сборка)
  rezume-glazkova-ma.pdf       исходное резюме для скачивания
scripts/check-assets.mjs       предполётная проверка путей
.github/workflows/deploy.yml   публикация на GitHub Pages
```

## Дизайн

За основу взята схема `ibm` (IBM Carbon) из
[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md),
переведённая в тёмную тему Carbon Gray 100 — ближе к чертёжной подаче:

* квадратные углы (0–2 px) и волосяные линии вместо теней;
* IBM Plex Sans 300 для заголовков, IBM Plex Mono для технических подписей;
* единственный хроматический акцент — Carbon Blue 50 `#4589ff`;
* подложка в виде миллиметровой сетки, уголки рамки как на листе чертежа.

Шрифты лежат в репозитории, а не подключаются с Google Fonts: страница
одинаково быстро открывается там, где внешние CDN недоступны.

## Анимации

Два эффекта, оба на CSS-переходах — JS только расставляет классы и индексы:

* **`.t-stream`** — появление по словам. JS разбивает текст элемента на `span.t-stream-w`,
  кладёт порядковый номер в `--i`, задержку считает `transition-delay`. Применён
  к специальности в шапке и подписи под фотографией.
* **`.t-stagger`** — построчное появление со сдвигом и размытием. Классы
  `t-stagger-line` расставлены в разметке, индексы — тоже через `--i`. Применён
  к имени в шапке, карточкам портфолио и блоку контактов.

Шапка стартует сразу после загрузки, остальное — при попадании в экран
(тот же `IntersectionObserver`, что показывает блоки).

Содержимое никогда не зависит от анимации:

* всё спрятано только под классом `js-reveal` на `<html>`;
* класс ставит встроенный скрипт в `<head>` — иначе текст успевает мигнуть
  до запуска модуля;
* если модуль не стартовал за 3 секунды, скрипт снимает класс и страница
  показывает всё как есть;
* при `prefers-reduced-motion: reduce` анимации не включаются вовсе.

Параметры (скорость, задержка, размытие, дистанция) вынесены в переменные
`--stream-*` и `--stagger-*` в `:root`.

## Что считается автоматически

Эти значения **не нужно обновлять руками** — они пересчитываются при каждом
открытии страницы:

| Значение | Откуда берётся |
| --- | --- |
| Возраст | `BIRTH_DATE` в `assets/js/data.js` |
| Общий стаж | `EXPERIENCE_PERIODS` — пересекающиеся месяцы не считаются дважды |
| Стаж на текущем месте | период с `id: 'olpuls'` |
| Число проектов и листов | длина `PROJECTS` и сумма `pages` |
| Год в подвале и дата в шапке | системная дата |

Месяцы считаются включительно — так же, как на hh.ru: «май — июнь» это 2 месяца.
Русские окончания («год», «года», «лет») подбираются функцией `plural`.

## Просмотрщик чертежей

Чертежи открываются в собственной полноэкранной модалке, а не во встроенном
просмотрщике браузера — никакой серой панели с кнопками сверху. Лист рисуется
через PDF.js в два слоя `<canvas>`:

* **базовый** — страница целиком в масштабе «вписать», при зуме только двигается
  трансформом, поэтому картинка никогда не пропадает;
* **детальный** — только видимая область в текущем масштабе. Благодаря этому
  чертёж остаётся чётким даже на 2000 %, а размер канвы не выходит за лимиты
  мобильных браузеров.

Управление:

| Действие | Мышь / тачпад | Сенсор | Клавиатура |
| --- | --- | --- | --- |
| Масштаб | колесо | щипок | `+` `−` |
| Вписать в экран | кнопка или клик по проценту | — | `0` |
| Сдвиг | перетаскивание | перетаскивание | — |
| Быстрый зум | двойной клик | двойное касание | — |
| Листы | кнопки, миниатюры | то же | `←` `→`, `Home`, `End` |
| Во весь экран | кнопка | кнопка | `F` |
| Закрыть | кнопка | кнопка | `Esc` |

PDF конкретного листа загружается только при переходе на него, поэтому открытие
проекта не тянет все 12 МБ сразу.

## Локальный запуск

Нужен любой статический сервер — модули ES и PDF.js не работают по `file://`.

```bash
python3 -m http.server 4173
```

Затем открыть <http://localhost:4173>.

## Деплой

Публикация настроена через GitHub Actions: пуш в `main` запускает проверку путей
и выкладывает репозиторий на Pages как есть.

Что нужно включить один раз в настройках репозитория:
**Settings → Pages → Build and deployment → Source → GitHub Actions**.

Все ссылки на ресурсы в коде относительные, поэтому сайт одинаково работает
и на своём домене, и на подпути `nvolnukhin.github.io/rezume_glazkova/`.

Файл `.nojekyll` обязателен: без него Pages пропустил бы служебные пути.

### Свой домен и HTTPS

Сайт живёт на **glazkova-ma.ru**. Домен куплен на reg.ru, DNS держит Cloudflare,
содержимое по-прежнему отдаёт GitHub Pages. Всё, кроме самого домена, бесплатно.

Схема получилась не самой очевидной, поэтому по порядку.

**Почему не напрямую GitHub Pages.** GitHub не проходит собственную DNS-проверку
для этого домена: в Settings → Pages висит `DNS check unsuccessful (InvalidDNSError)`,
и из-за этого он не выпускает сертификат. Записи при этом объективно корректны —
проверялось делегирование от корневых серверов, авторитетность NS, отсутствие
DNSSEC и CAA, формат файла `CNAME`. Не помогли ни добавление AAAA, ни пересоздание
домена, ни смена DNS-провайдера. Судя по
[community#209249](https://github.com/orgs/community/discussions/209249), с тем же
симптомом столкнулись и другие домены в зоне `.ru`; у GitHub это не признано
инцидентом и не исправлено.

**Как решено.** Cloudflare проксирует трафик и отдаёт свой сертификат:

```
браузер → (HTTPS, сертификат Cloudflare) → Cloudflare → (HTTPS) → GitHub Pages
```

Сертификат GitHub больше не нужен, и красная плашка в Settings → Pages теперь
просто косметика — её не починить, потому что в DNS стоят адреса Cloudflare,
а не GitHub. Это ожидаемо, трогать ничего не надо.

**Настройки Cloudflare, которые нельзя менять:**

* **SSL/TLS → Full.** Именно Full, выставленный вручную. `Full (Strict)` уронит
  сайт: GitHub отдаёт на нашем домене чужой сертификат `*.github.io`, и строгая
  проверка имени его отклонит. Режим `Automatic SSL/TLS` тоже не подходит — он
  со временем сам повышается до Strict.
* **Все записи — Proxied** (оранжевое облако). С серым облаком вернётся исходная
  проблема: браузер пойдёт прямо в GitHub, где сертификата нет.
* **Always Use HTTPS** — включён, редирект `http → https` делается на границе
  Cloudflare.

**DNS-записи в Cloudflare** (origin для прокси):

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `glazkova-ma.ru` | `185.199.108.153` … `185.199.111.153` (4 шт.) |
| AAAA | `glazkova-ma.ru` | `2606:50c0:8000::153` … `8003::153` (4 шт.) |
| CNAME | `www` | `nvolnukhin.github.io` |

Те же записи продублированы в зоне reg.ru как резерв на случай отката на её NS.

**Файл `CNAME` в корне репозитория удалять нельзя** — именно по нему GitHub Pages
понимает, чей сайт отдавать для этого имени. Мы публикуемся своим Actions-воркфлоу,
а не из ветки, и в этом случае
[GitHub не создаёт его автоматически](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).
`check-assets.mjs` следит за наличием файла и сверяет домен с абсолютными
ссылками в мета-тегах.

При смене домена правятся четыре места: `CNAME`, мета-теги `og:*` и `canonical`
в `index.html`, DNS и NS у регистратора. Расхождение между первыми двумя поймает CI.

**Запасные варианты,** если Cloudflare однажды станет неудобен: вернуть серые
облачка и ждать, пока GitHub починит проверку, либо снять custom domain —
тогда `https://nvolnukhin.github.io/rezume_glazkova/` сразу отдаётся по HTTPS
с валидным сертификатом.

## Как обновлять

* **Текст разделов** — прямо в `index.html` (он статический, чтобы страница
  читалась поисковиками и работала без JavaScript).
* **Новая работа в портфолио** — положить PDF в `assets/portfolio/`, обложку
  в `assets/portfolio/thumbs/`, добавить объект в `PROJECTS` и указать
  правильное число страниц в `pages`.
* **Новое место работы** — добавить период в `EXPERIENCE_PERIODS` (тогда стаж
  пересчитается сам) и блок `<li class="job">` в `index.html`.

Перед коммитом полезно прогнать проверку:

```bash
node scripts/check-assets.mjs
```
